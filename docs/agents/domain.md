# Domain guidance

Read root `CONTEXT.md` and relevant `docs/adr/` decisions before exploring or
changing the public engine. Use the glossary vocabulary in code, documentation,
issues, and reviews. Surface a missing definition or an ADR conflict explicitly.

Accepted ADR semantics remain authoritative; mark historical or superseded policy
clearly. ADR-0012 separates capability from operator policy, ADR-0013 defines the
mutation gate, ADR-0007 defines the public boundary, and ADR-0016 describes update
previews. Use source and offline tests to verify shipped behaviour.
